# SuperSampler 测试总览（testplan）

> 配套文档：`unit-tests.md`（单测用例矩阵）、`integration-tests.md`（模拟从站集成）、`acceptance.md`（验收清单）。
> 依据：docs/00–04、`src/` 现有契约与实现、`Config/上位机配置.v3.xml`、`_simulator_design/` 模拟从站。
> 测试框架：仅 **xunit 2.6.6**，net462（引用 net46 产品程序集），零第三方依赖。
> 只有 `SuperSampler.Abstractions` 与 `SuperSampler.Core`（事件总线/错误/值模型）已落码；其余模块由实现者并行编写，**用例标注「待新增」的即为被测模块交付后补测**。

---

## 1. 分层与测试策略

| 层 | 策略 | 环境 | 用例数量级 |
|---|---|---|---|
| **单元测试** | 纯函数/单类，无 I/O、无真实通讯 | xunit [Theory]/[Fact]，进程内 | ~140（见 unit-tests.md） |
| **集成测试** | 接真实模拟从站（mbserver），走完整采集链路 | localhost:1502 / :1503，需 Python 驱动脚本 | 16 场景（见 integration-tests.md） |
| **验收** | 全部可勾选条目 | 构建 + 单测 + 集成 | acceptance.md |

**测试金字塔原则**：Codec / 配置加载 / 错误分类 / 写管道是纯逻辑与最易错处，全部以**单测**精确锁定；链路口与原码只需覆盖到「主站帧正确 + 能解析」集成层即可，不追求覆盖率。

**重要基线**：项目现处于「实现中」，`OnlyCode` 三件已落码（事件总线、错误模型、值模型），**当前 25 个单测全部通过**。本计划在所有「待新增」用例上标注了**被测对象 + 输入 + 期望**，实现者交付模块后按 ID 逐条补齐即可。

## 2. 被测模块清单与优先级

| 优先级 | 模块 | 依赖 | 单测分组 | 说明 / 风险 |
|---|---|---|---|---|
| **P0** | Codec 编解码 | 无 | `C-*`、`CF-*` | 字序×类型矩阵是最易错处；一旦错，全链路解析全错 |
| **P0** | Codec 展示管道（Format） | Codec | `CF-*` | decimals/Map/BCD/字符串/边界，含 NaN/Inf 钳制 |
| **P0** | Config 加载 + 校验 | 无 | `CG-*`、`CGV-*` | PLC 编址换算、swap 别名、模板继承、Defaults 链、${i18n}、14 条校验规则 |
| **P0** | 错误模型 → ErrorClass 映射 | Values | `E-*` | 8 个错误族映射；Modbus 异常码 01..0B 分类归属；Permanent 不重试 |
| **P1** | 写管道四态 | Facade | `W-*` | Succeeded/Failed/Indeterminate/Rejected 触发；超时绝不自动重试（安全） |
| **P1** | 事件总线 | 无 | `B-*`（已有 25 个覆盖一部分） | 有界队列、溢出、保序、异常隔离、批量、Seq |
| **P1** | PointRegistry（寻址） | Config | `R-*` | N:M 寻址、块内共享、（deviceId,pointId）唯一 |
| **P1** | ValueCache | 无 | `VC-*` | 线程安全读写、质量置换、陈旧判定 |
| **P2** | Modbus 主站帧（Driver） | Codec | `M-*`（集成） | TCP / RTU-over-TCP 帧组装、CRC、事务号（放集成层为主） |
| **P2** | 传输层 TCP/RTU | — | 集成 `IT-*` | 连接、重连、超时、慢响应 |
| **P2** | Scheduler 调度 | Config | `S-*` | 扫描组、块读合并、预算、onDemand 触发 |
| **P2** | 门面 IDeviceManager / IModbusDebugTool | 全部 | `F-*`、集成 | 薄壳：GetValue/GetValueDetail/SetValue + 原始读写 |

## 3. 单测/集成/验收的关系

```
unit-tests.md   纯逻辑锁定（确定性输入→确定性输出），覆盖 Codec/Config/Error/Write/Event
integration-tests.md   验证「文档里的值」端到端能读出来（mbserver）
acceptance.md     验收门：构建绿 + 单测全绿 + 集成场景全过
```

**优先级执行顺序**（每步都必须绿再进下一步）：
1. Codec（`C-*`、`CF-*`）——最底层，先锁字序与类型，避免上游拿错数值
2. 错误模型与写四态（`E-*`、`W-*`）——安全关键（写不确定不重试）
3. 配置加载与校验（`CG-*`、`CGV-*`）——一切运行时的源头
4. PointRegistry / ValueCache / 门面（`R-*`、`VC-*`、`F-*`）
5. 事件总线补充 + Scheduler（`B-*` 扩充、`S-*`）
6. 集成（编写 mbserver 场景脚本 + 逐场景验证）
7. 验收（acceptance.md）

> 单测可达的绝不放集成：Codec 字序矩阵、错误映射、配置校验在数百个确定性用例里远比真实从站可靠。集成的价值在于「端到端连通 + 报文级正确」，不是覆盖率。

## 5. 测试数据来源约定

- **单测寄存器一律用十六进制**（`0x3FC0` 等），十六进制是「线上字」最直接的表达，避免十进制换算出错。
- 字序字节规则（整个 codec 矩阵共用，见 unit-tests.md §1.1）：
  - `ABCD`=大端、`BADC`=字节交换、`CDAB`=字交换（国内最常见）、`DCBA`=小端。
- 集成层期望值直接引用 `_simulator_design/启动与验证.md` 的既定值（如 400071 → int16≈255±2）。
- 时间类用例固定用 `DateTimeOffset(2026,9,11,10,0,0,+08:00)`。

## 6. 已知风险（详见各文档）

| 风险 | 模块 | 缓解 |
|---|---|---|
| 字序语义被误用（ABCD 实际对应何种排布有歧义） | Codec | 单测以**线上原始字**为准锁定，不信字母命名 |
| 写超时被自动重试导致命令重复触发（安全） | Write | `W-*` 专门锁 Indeterminate 绝不自动重试 |
| 渲染报警/审计静默漏记（新增错误类型逃脱订阅） | EventBus | 基接口订阅用例如 `IErrorEvent` / `IPermanentError` 已被覆盖 |
| 模拟器做不了按点异常码 / 坏 CRC / 比例丢包 | 集成 | 在框架侧用 Mock/代理注入（integration §6 注明边界） |
