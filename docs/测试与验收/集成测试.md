# SuperSampler 集成测试（integration）

> 用 `mbserver.exe` 加载 `_simulator_design/supermodbus_sim_tcp.mbs`（:1502，8 从站）与
> `supermodbus_sim_rtu_tcp.mbs`（:1503，3 从站）起真实模拟从站，逐场景验证端到端链路。
> 每条场景给出：**启动命令 → 框架配置要点 → 采哪个点位 → 期望解析结果（精确字符串）**。
> 地址约定（全局一致，见 `_simulator_design/启动与验证.md`）：
> 保持=400001+off、输入=300001+off、线圈=off+1、离散=100001+off。**模拟器寄存器为 0 基；主站配 plc 地址按文档换算。**

---

## 0. 前置与启动

```bat
mbserver -f supermodbus_sim_tcp.mbs        rem TCP :1502
mbserver -f supermodbus_sim_rtu_tcp.mbs    rem RTU-over-TCP :1503（可与上同开：同进程多 Port）
```

- 需 Python 3.6+ 驱动动态脚本；否则用 GUI `Simulation→Action` 补动态。
- 用 `mbclient` 先人工 poke 每个场景（`_simulator_design/启动与验证.md` §3）确认从站就绪，再跑框架场景。

### 场景 3：位 / 位域 / 状态字（TYPEDEMO offset200 → 400201）[P1]

### 场景 4：四数据区（TYPEDEMO）[P1]

| 区 | 位置 | 期望 |
|---|---|---|
| 保持 4x | 400001 | int16 -12345 |
| 输入 3x | 300001 | int16 **-7777**；300002-3 float32 **9.81**；300004-5 uint32 **20260911** |
| 线圈 0x | offset0.. | 前 3 位 `0,1,1` 由 `(i%5)<3` → offset0、1=false,2,3... 依公式 |
| 离散 1x | offset0.. | `((i>>2)&1)==0` 周期 |

### 场景 5：多字序（WO_ABCD/BADC/CDAB/DCBA，unit 11-14, :1502）[P0]

同一偏移，同一 dataType，四台 device 各自 `swap`（对应 registerOrder）：

| unit | swap | offset0 float32 | offset2 int32 | 期望 |
|---|---|---|---|---|
| 11 ABCD | none | 3.14 | -1234567 | 同上 |
| 12 BADC | byte | 3.14 | -1234567 | 同上 |
| 13 CDAB | word | 3.14 | -1234567 | 同上 |
| 14 DCBA | word_byte | 3.14 | -1234567 | 同上 |

> 验证要点：每台用**匹配的 swap**都能读出同一个逻辑值；再 RawRead 原始 16 位字，断言四台同寄存器**字形互不相同**（`uint16` 原始值不同）。**结论以原始字为准，不信字母命名。**

### 场景 6：动态数据（PROCESS, unit 2, :1502）[P1]

| 地址 | 期望现象 |
|---|---|
| 400011-12 float32 | 设定值 ≈ `25+sin(dt)`，两次采样在变化且在 ±1% 区间 |
| 400021-22 float32 | 过程值基值 ≈ 24.5±0.5，在变化 |
| 400031 int16 | 计数器**递增**（两次采样必不同） |
| 400041-42 float32 | 0..100，在范围内变化 |
| 400051 int16 | 泵转速 0..2999 循环 |
| 线圈 bit2 | **每 20 周期翻转一次**（两次采样必不同） |

> 断言方式：同点采 2 次，值变 + 落在合理区间 = 通过（不锁死具体数字）。

### 场景 7：RTU-over-TCP 多从站（RTU_SLAVE1/2/3, unit 10/11/12, :1503）[P0]

| host:port=localhost:1503 | unit | 期望 |
|---|---|---|
| RTU_SLAVE1 | 10 | int16/uint16/float32/string 各读对（区域内给定值） |
| RTU_SLAVE2 | 11 | 同上块 |
| RTU_SLAVE3 | 12 | 同上块 |

> 验证「一条串口总线上多从站」——同一 Transport(variant=rtuovertcp) 下多 Device，各自 unitId 正确路由。

### 场景 8：块读 + 合并 + 分块（TYPEDEMO 大块）[P1]

| 块 | 期望 |
|---|---|
| 区 A offset300..549（400301..） | `(i*7+123)&0xFFFF` 连续读一次（≤125 字则需分块） |
| 区 B offset1000..1249 | `(255-i)&0xFFFF` |
| 区 C offset2000..3247（1248 字>125） | 驱动自动按 maxRegistersPerRead=125 分几次 FC03，结果拼接完整 |
| 区 float 数组 offset5000..5299 | 300 个 sin(i*0.1)，每个可 float32 解析 |

### 场景 9：异常路径——慢响应（Device Delay）[P1]

- mbserver 对该 device 设 Delay(msec)=500，主站 requestTimeoutMs=1000，仍能读到值（未超时）。
- 把 Delay 调到 2000（>超时 1000）：读该点 → 触发 `TimeoutError` 事件，质量置 Bad，连续超时 3 次升级 LinkDown/重连（观察事件类别）。

### 场景 10：异常路径——超时（读未绑定 unit 99，RTU 线）[P1]

- 对 host:1503、unit=99 发读 → 服务器不回包 → 期望 `TimeoutError`（Transient），重试后退避，连超 escalateAfter 后 LinkDown。**不抛 SocketException 泄漏到调度层。**

### 场景 11：异常路径——写拒绝（READONLY, unit 4）[P0]

- 向 READONLY 400001 写 → 服务器回异常码(0x02 / 0x86) → 期望 **WriteOutcome.Failed**，`DeviceExceptionError` ExceptionCode 反映码值。读正常。

### 场景 12：异常路径——越界（地址超内存上界）[P1]

- 读 TYPEDEMO 保持 406000+（超 6000 字上界）→ 回 IllegalDataAddress(0x02) → 归 **Permanent**，重试计数 0，置 Bad。

### 场景 13：TriggerRead / RawRead 手动读取（IModbusDebugTool）[P2]

| 调用 | 期望 |
|---|---|
| `TriggerReadAsync("dev","point")` | 走该点完整解析管道，结果写缓存并返回 PointValue |
| `TriggerReadAsync` 未知 id | KeyNotFoundException |
| `TriggerBlockReadAsync("blockId")` | 返回读到的寄存器数量；未知 blockId 抛异常 |
| `RawReadAsync(d, HoldingRegister, addr, count)` | 返回原始 `ushort[]`/`byte[]`（大端拼接），不解析 |
| `RawReadAsync`（Diagnostics@allowRawAccess=false） | 拒绝（开关未开） |
| 「odemand 点」Trigger | 进配方画面才读的点可由 Trigger 触达（CGV-11 反向证明） |

### 场景 14：写成功 + verify 回读（BOUNDARY/PROCESS 可写点）[P1]

- 向可写点写设定值 → Succeeded；verify=true 时回读与所写一致。
- 写边界（±Inf / NaN / 空串 / 0xFFFF / 满长串 offset40）→ 各按类型成功或由 Write@min/max 拒绝（Rejected）。

### 场景 15：写超时 → Indeterminate 绝不重试（安全）[P0]

- 对该点临时 Device Delay=2000（>requestTimeoutMs=1000）写 → 报文已发出但无应答 → **Indeterminate**；
- **断言重试次数为 0**，且释放 WriteIndeterminateError 事件；verify=true 时自动回读一次。

### 场景 16：多从站并发 + 扫描组节奏 [P2]

- 同一条 :1502 上同时采 unit1(fast+normal+slow) 与 unit2，断言各 ScanGroup 以 200/1000/10000ms 近似节奏刷新，值各自解析正确、互不串台。

## 2. 模拟器能力边界（本方案做不了的，按 _simulator_design 注）

| 场景 | 状态 | 主站侧替代 |
|---|---|---|
| **按点注入异常码序列**（如特定点位回 0x02/0x04） | ❌ 无 | 框架单测用 Mock Driver 注入 `DeviceExceptionError` |
| **比例丢包 / 坏 CRC** | ❌ 无 | 主站与 mbserver 间挂丢包/坏 CRC 代理（留接口，非本方案） |
| 双点量程换算算法 | ⚠ 模拟器只给原始字 | 由主站 `/10` 与双点映射配置完成（场景 1） |
| ASCII/UTF-8 真正区分 | ⚠ 需点位级 StringEncoding 区分 | 用 TYPEDEMO offset40 的 UTF-8 中文串验证 |
| BCD / DateTime 原生类型 | ⚠ 无，模拟器用原始字/epoch/字符串承载 | 用 `0x1234` 原始字与 epoch 秒手工核 |

> 能做的都做（场景 1–16）；做不了的，前缀「单测 Mock + 代理留接口」，不让集成覆盖归零。
